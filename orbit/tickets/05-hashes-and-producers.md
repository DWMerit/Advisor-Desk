# 05 — IDENTICAL_BYTES and PRODUCES

## Do

**`IDENTICAL_BYTES`** — sha256 every indexed file; emit an edge per matching pair. Pure observation, no interpretation, and the word *duplicate* never appears in output.

**`PRODUCES`** — generator → artifact, on an evidence ladder:
- artifact header names its producer (`Generated by X`, `@generated`, `DO NOT EDIT`) → strongest
- config or manifest declares input → output
- a script contains a literal write path → weakest

Take only the first token of a parsed producer name; header comments carry trailing junk (`Generated by scripts/build.py -- DO NOT EDIT -->`).

## Done when

An identical-bytes count is **never reported alone** — always alongside how many of those pairs carry any provenance evidence at all.

## Why that pairing is mandatory

On one real repo: 28 identical-byte pairs, **0 `PRODUCES` edges**. Every pair was a workbench file matching a published file — one pipeline, run 28 times — and the provenance explaining it was entirely invisible. Byte-identity and provenance are usually the same phenomenon, and only the first is easy to see. A bare hash-match count over-reads badly.

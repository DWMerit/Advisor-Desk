# 05 — Identical bytes, reported with provenance

**Blocked by:** 02
**Demo when done:** byte-identical pairs listed alongside how many of them carry any provenance evidence at all.

## Do

**`IDENTICAL_BYTES`** — sha256 every indexed file; emit an edge per matching pair. Pure observation. The word *duplicate* never appears in output.

**`PRODUCES`** — generator to artifact, on an evidence ladder, strongest first:
1. artifact header names its producer (`Generated by X`, `@generated`, `DO NOT EDIT`)
2. config or manifest declares input → output
3. a script contains a literal write path

Take only the **first token** of a parsed producer name. Header comments carry trailing junk: `Generated by scripts/build.py -- DO NOT EDIT -->`.

## Acceptance

- [ ] Identical-byte count is **never emitted alone** — always with the count of those pairs carrying provenance evidence
- [ ] A pair where both files carry a generation header links to the producer
- [ ] A pair with no provenance is reported as exactly that, with no inference about why
- [ ] Producer parsing does not capture trailing comment syntax
- [ ] Output contains no forbidden vocabulary word

## Watch for

On one real repository: **28 identical-byte pairs, 0 `PRODUCES` edges.** Every pair was a workbench file matching a published file — one pipeline run 28 times — and the provenance explaining it was entirely invisible.

Byte-identity and provenance are usually the same phenomenon, and only the first is easy to see. A bare hash-match count over-reads badly, which is why the pairing is mandatory rather than nice to have.
